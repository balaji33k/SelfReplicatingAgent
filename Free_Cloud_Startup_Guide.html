1. Overview — Why Free Tiers Work for Startups

Most startups waste money on cloud infrastructure before they even have users. The good news: modern free tiers from cloud platforms are powerful enough to run real production applications with thousands of users — completely free.

✅ Key Insight: A well-assembled free stack can handle 5,000–20,000 monthly active users with zero monthly cost. You only need to pay when you have real revenue and real scale.

11. Step-by-Step Setup Guide

Setting Up the Full Free Stack (SaaS App) in 1 Hour

1
Create Supabase Project (5 minutes)
  1. Go to supabase.com → Sign up with GitHub
  2. Click "New Project" → Choose a name and region (Singapore for India)
  3. Save your Project URL and API Keys (anon + service_role)
  4. Create your first table in the SQL Editor
2
Set Up Supabase Auth (5 minutes)
  1. In Supabase dashboard → Authentication → Providers
  2. Enable: Email, Google, GitHub
  3. For Google: Create OAuth app at console.cloud.google.com
  4. Add your domain to "Redirect URLs"
3
Deploy Frontend to Vercel (5 minutes)
  1. Push your code to GitHub
  2. Go to vercel.com → Import Git Repository
  3. Add environment variables: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY
  4. Deploy → get your yourapp.vercel.app URL
4
Deploy Backend to Koyeb (10 minutes)
  1. Go to koyeb.com → Create Account (no card needed)
  2. New App → Deploy from GitHub
  3. Set environment variables: SUPABASE_URL, SUPABASE_SERVICE_KEY
  4. Set the run command: python app.py or node server.js
  5. Get your yourapp.koyeb.app URL
5
Set Up Cloudflare (10 minutes)
  1. Buy a domain (cheapest: Namecheap ~₹700/year for .com)
  2. Go to cloudflare.com → Add Site
  3. Change nameservers at your registrar to Cloudflare's
  4. Add DNS records pointing to Vercel and Koyeb
  5. SSL automatically enabled
6
Set Up Cloudflare R2 for File Uploads (10 minutes)
  1. Cloudflare Dashboard → R2 → Create Bucket
  2. Create API token with R2 permissions
  3. In your backend, use the S3-compatible API (R2 works with any S3 SDK)
  4. Add a custom domain to your bucket for direct file serving
import boto3
s3 = boto3.client('s3',
    endpoint_url='https://<accountid>.r2.cloudflarestorage.com',
    aws_access_key_id='R2_ACCESS_KEY',
    aws_secret_access_key='R2_SECRET_KEY'
)
7
Set Up Email with Resend (5 minutes)
  1. Go to resend.com → Create account
  2. Add and verify your domain (Cloudflare DNS makes this easy)
  3. Get API key → add to environment variables
  4. Send emails: POST to https://api.resend.com/emails
import urllib.request, json
data = json.dumps({
    "from": "noreply@yourdomain.com",
    "to": user_email,
    "subject": "Welcome!",
    "html": "<h1>Welcome to our app!</h1>"
}).encode()
req = urllib.request.Request(
    "https://api.resend.com/emails",
    data=data,
    headers={"Authorization": f"Bearer {RESEND_API_KEY}",
             "Content-Type": "application/json"}
)
urllib.request.urlopen(req)
8
Set Up Monitoring (5 minutes)
  1. uptimerobot.com → Add your app URL as HTTP monitor → every 5 minutes (also prevents Render from sleeping)
  2. sentry.io → Create project → add 3 lines of code for error tracking
  3. Cloudflare Analytics → already working — see traffic, threats, performance

Traffic Spike Strategy

If your app goes viral (e.g., Product Hunt launch, news article), here's how to handle it on free tiers:

  1. Put Cloudflare in front of everything — it absorbs the spike at the CDN layer. Most requests for static content never reach your server.
  2. Cache aggressively — use Cloudflare Cache Rules to cache API responses for 60 seconds. A spike of 10,000 users becomes 1 request per endpoint per minute to your server.
  3. Serve static where possible — pre-generate pages (static site generation) so Cloudflare serves them, not your Koyeb instance.
  4. Rate limit at Cloudflare — free WAF rules can limit requests per IP, protecting your backend.
Real example: A startup landing page with Cloudflare + Vercel can handle 10 million visits in a day for $0. The CDN does all the work. Your backend only gets hit for actual user actions (login, submit, etc.).
